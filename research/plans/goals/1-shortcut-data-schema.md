## Objective

Design and implement the Prisma schema with all models required by the PRD. Export corresponding TypeScript types from `packages/core`. No seed data, no API endpoints, no UI.

---

## Work breakdown

### Phase 1 — TRD (this run)
1. Read and analyze PRD to understand all required models and relationships.
2. Draft TRD: define all models, fields, relationships, key design decisions.
3. Commit TRD + plan, push branch, open draft PR.
4. Wait for TRD Watcher approval before writing any schema code.

### Phase 2 — Schema implementation (after TRD approved)

**Step 1: Prisma schema in `database/schema.prisma`**
- Define `Category` model (name, slug, description, icon)
- Define `Platform` model (name enum: WINDOWS, MACOS, LINUX)
- Define `Application` model (name, slug, description, belongs to Category)
- Define `Shortcut` model (command, description, context/scope, chord support)
- Define `ShortcutBinding` model (links Shortcut ↔ Platform with keyCombo + structured modifiers)
- Define join table / relation for Application ↔ Shortcut
- Add unique constraints and indexes

**Step 2: TypeScript types in `packages/core/src/types.ts`**
- Export `Platform` enum
- Export `Modifier` enum (CTRL, CMD, ALT, OPTION, SHIFT, SUPER, WIN)
- Export interfaces: `ApplicationRecord`, `ShortcutRecord`, `ShortcutBinding`, `CategoryRecord`
- These types mirror the Prisma models for use in web/desktop/overlay without importing Prisma client

**Step 3: Prisma generate + migration**
- Run `prisma generate` to generate the client
- Create initial migration: `prisma migrate dev --name init-shortcut-schema`
- Verify migration runs clean on a fresh PostgreSQL instance

**Step 4: Core package wiring**
- Update `packages/core/src/index.ts` to export types
- Verify TypeScript compiles with no errors

**Step 5: Tests**
- Verify schema migrates cleanly (migration smoke test)
- Verify Prisma client generates with no TypeScript errors
- Verify core types compile and are importable
